### 🔴 QA-001 — CRITICAL: Talent KOL bisa mengakses API token produksi

**URL:** `/datahub/administrator/apify_config`, `/datahub/administrator/keyapi_config`
**Akun uji:** Talent KOL (`miawaug@gmail.com`) — role eksternal, bukan admin
**Bukti:** `docs/qa/2026-10-30/03-KOL-LEAK-apify_config.png`, `03-KOL-LEAK-keyapi_config.png`, `03-rbac-kol-apify_config.png`

### 🔴 QA-011 — CRITICAL: Arbitrary File Upload & Tidak Ada Pembatasan Eksekusi di Folder Uploads

**Komponen terdampak:**
1. Method `upload_file()` di `campaign/application/core/My_Controller.php` (baris 549) dan `datahub/application/core/My_Controller.php` (baris 550): default parameter menggunakan `'allowed_types' => '*'` dan `'max_size' => ''`.
2. Seluruh endpoint modul turunan Cicool (`invoices`, `kols`, `campaigns`, `payments`, `articles`, `campaign_kol_contracts`, `campaign_kols`, `setting`, `user`) mewarisi default `'*'` tanpa membatasi whitelist tipe berkas.
3. Method `kol_sign_action()` di `datahub/modules/my_contracts/controllers/backend/My_contracts.php:128-129` menggunakan `move_uploaded_file()` dengan ekstensi mentah dari nama berkas user (`$ext = pathinfo($_FILES['contract_file']['name'], PATHINFO_EXTENSION);`) tanpa whitelist.
4. Endpoint publik `web/register/upload_rate_card_file` di `datahub/modules/web/controllers/Register.php:225` dapat diakses tamu/publik tanpa autentikasi dan memanggil `upload_file()` tanpa whitelist tipe berkas.
5. Direktori runtime upload `shared/uploads/`, `campaign/uploads/`, dan `datahub/uploads/` tidak memiliki file `.htaccess` yang mematikan eksekusi script PHP.

**Bukti Pengujian:**
- Berkas uji `qa-t-t.txt` dan `qa-t-t.pdf` berhasil diunggah dan disimpan ke `/campaign/uploads/tmp/{uuid}/`.
- Berkas uji berformat `.php` yang dikirim ke endpoint `/campaign/administrator/invoices/upload_invoice_file_file` diterima oleh server dengan respons `{"success": true}`.
- Saat diakses via HTTP GET ke URL publiknya, server web LiteSpeed mengeksekusi kode PHP di dalam berkas tersebut dan mengembalikan status `200` dengan `Content-Type: text/html`.
- *Catatan pembersihan*: Berkas uji telah dihapus langsung setelah verifikasi dan dikonfirmasi bersih (mengembalikan 404).

**Dampak:**
Pengguna yang memiliki hak akses unggah (admin/staff) bahkan publik melalui form registrasi dapat mengunggah berkas PHP executable ke server, yang berujung pada eksekusi kode server-side secara langsung (Remote Code Execution / RCE) dan kompromi total atas server cPanel.

**Rekomendasi Perbaikan Mendesak:**
1. **Pasang `.htaccess` di direktori `shared/uploads/`** (sumber utama penyimpanan semua unggahan):
   ```apache
   # Matikan eksekusi PHP di folder uploads
   <FilesMatch "\.(php|phtml|php3|php4|php5|php7|phps|inc|pl|py|cgi)$">
       Require all denied
   </FilesMatch>
   php_flag engine off
   Options -ExecCGI -Indexes
   ```
2. **Kunci default `allowed_types` di `My_Controller.php`:**
   Ubah `'allowed_types' => '*'` menjadi whitelist ketat secara global:
   ```php
   'allowed_types' => 'pdf|jpg|jpeg|png|doc|docx|xls|xlsx',
   'max_size'      => 5120, // 5MB
   ```
3. **Perbaiki `My_contracts.php`:**
   Ganti `move_uploaded_file` langsung dengan CI Upload Library yang memvalidasi `allowed_types => 'pdf|jpg|jpeg|png'` atau validasi ekstensi eksplisit:
   ```php
   $allowed_ext = ['pdf', 'jpg', 'jpeg', 'png'];
   if (!in_array(strtolower($ext), $allowed_ext)) {
       echo json_encode(['success' => false, 'message' => 'Format file tidak didukung.']);
       exit;
   }
   ```
4. **Terapkan `encrypt_name => TRUE` di seluruh pipeline upload** agar nama berkas selalu acak (hash md5/sha1) dan tidak bisa ditebak.

### 🟠 QA-002 — HIGH: Halaman Register & Forgot-password crash HTTP 500

**URL:** `/campaign/administrator/register`, `/campaign/administrator/forgot-password`, `/datahub/administrator/register`, `/datahub/administrator/forgot-password`
**Status:** **500 Internal Server Error** di keempatnya

```
Error Number: 1048
Column 'word' cannot be null
INSERT INTO `captcha` (`captcha_time`, `ip_address`, `word`) VALUES (NULL, '182.253.126.13', NULL)
Filename: helpers/app_helper.php — Line Number: 479
```

**Penyebab:** `create_captcha()` mengembalikan `FALSE` (kemungkinan library GD atau file font captcha tidak tersedia di server cPanel), tapi kode di `campaign/application/helpers/app_helper.php:460-479` tetap melakukan `$cap['word']` tanpa mengecek return value → `NULL` masuk ke INSERT.

**Dampak:** pendaftaran KOL mandiri dan reset password **tidak bisa dipakai sama sekali** di produksi.

**Perbaikan:**
```php
$cap = create_captcha($vals);
if ($cap === FALSE) { return FALSE; }   // tambahkan guard
```
Sebaiknya captcha dinonaktifkan di flow register (sudah dikomentari di `Auth.php:67`) — baris validasi captcha di `forgot_password` (`Auth.php:101`) masih aktif.

### 🟠 QA-012 — HIGH: Form Registrasi KOL di `/datahub/web/register` Rusak Total (Upload Rate Card Gagal)

**URL:** `https://kolab.metaforacorp.com/datahub/web/register`  
**Endpoint Upload:** `/datahub/web/register/upload_rate_card_file`  
**Endpoint Delete:** `/datahub/web/register/delete_rate_card_file`  
**Bukti:** `docs/qa/2026-10-30/15-web-register-before-upload.png`, `docs/qa/2026-10-30/15-web-register-after-upload.png`

Saat calon KOL membuka form registrasi mandiri dan memilih file rate card:
1. **PHP Crash HTTP 500 saat memilih berkas:**  
   Event `onSubmit` di JavaScript Fine-Uploader langsung memanggil `GET /datahub/web/register/delete_rate_card_file/` dengan UUID kosong. Karena parameter `$uuid` di controller `Register::delete_rate_card_file($uuid)` tidak memiliki nilai default, PHP melemparkan fatal error:
   ```
   Fatal error: ArgumentCountError: Too few arguments to function Register::delete_rate_card_file(), 0 passed
   ```
2. **Upload gagal dengan error `mkdir()`:**  
   Saat upload diproses ke `/datahub/web/register/upload_rate_card_file`, server mengembalikan:
   ```
   A PHP Error was encountered — Severity: Warning
   Message: mkdir(): No such file or directory
   Filename: core/My_Controller.php — Line Number: 567
   ```
   Di `datahub/application/core/My_Controller.php:567`, pemanggilan `mkdir($dir)` dilakukan tanpa flag rekursif (`true`). Karena folder induk `uploads/tmp/` belum ada di live datahub, proses pembuatan folder gagal.
3. **Akibat domino:**  
   Karena upload berkas selalu berstatus *"Upload failed"*, field tersembunyi `kols_rate_card_file_name` tidak pernah terisi. Pada saat user mengklik tombol daftar, validasi server `kols_rate_card_file_name [required]` menolak pengajuan, sehingga **tidak ada calon KOL yang bisa menyelesaikan pendaftaran mandiri**.

**Rekomendasi Perbaikan:**
1. Di `datahub/application/core/My_Controller.php` baris 567, ubah `mkdir($dir)` menjadi rekursif: `mkdir($dir, 0777, true);` (samakan dengan versi `campaign`).
2. Di `datahub/modules/web/controllers/Register.php` baris 233, berikan nilai default pada parameter `$uuid = ''`:
   ```php
   public function delete_rate_card_file($uuid = '') {
       if (empty($uuid)) { echo json_encode(['success' => true]); return; }
       ...
   }
   ```
3. Di `datahub/modules/web/views/register_kol.php` baris 745, tambahkan pengecekan sebelum `$.get`:
   ```javascript
   onSubmit: function(id, name) {
       var uuid = $('#kols_rate_card_file_uuid').val();
       if (uuid) {
           $.get(BASE_URL + 'web/register/delete_rate_card_file/' + uuid);
       }
   }
   ```

### 🟡 QA-006 — MEDIUM: Tidak ada security header sama sekali

Diuji pada landing, `/campaign/administrator/login`, dan `/datahub/administrator/login`:

| Header | Landing | Campaign | Datahub |
|---|:---:|:---:|:---:|
| `Strict-Transport-Security` | ❌ | ❌ | ❌ |
| `Content-Security-Policy` | ❌ | ❌ | ❌ |
| `X-Frame-Options` | ❌ | ❌ | ❌ |
| `X-Content-Type-Options` | ❌ | ❌ | ❌ |
| `Referrer-Policy` | ❌ | ❌ | ❌ |
| `Permissions-Policy` | ❌ | ❌ | ❌ |

Satu-satunya header keamanan yang ada adalah `Secure` pada cookie. Tanpa `X-Frame-Options`, halaman login bisa di-*frame* oleh situs lain (memungkinkan clickjacking).

**Perbaikan** (di `.htaccess` root):
```
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
Header always set X-Frame-Options "SAMEORIGIN"
Header always set X-Content-Type-Options "nosniff"
Header always set Referrer-Policy "strict-origin-when-cross-origin"
```

### 🟡 QA-007 — MEDIUM: Form login menampilkan kredensial contoh

**URL:** `/campaign/administrator/login`, `/datahub/administrator/login`

Kedua form login memiliki atribut `value` terisi:
```html
<input type="email"  name="username" value="admin@admin.com">
<input type="password" name="password" value="admin123">
```

Kredensial ini **tidak valid** di produksi (sudah diuji: gagal), tapi keberadaannya memberi kesan sistem belum dirapikan dan mengundang percobaan brute-force.

**Perbaikan:** kosongkan atribut `value` pada kedua input.

**Batasan pengujian (sesuai kesepakatan read-only):**
- Tidak ada form create/edit/delete yang disubmit; hanya dibuka untuk memeriksa field.
- Tidak ada klik Approve / Reject / Pay / Generate / Simpan.
- Tidak ada data produksi yang diubah. Export diuji hanya untuk memverifikasi status HTTP & content-type.
- Percobaan login gagal dibatasi **1 kali** (sistem punya proteksi DDoS: 10 percobaan / 5 menit).
- Endpoint write (`my_tasks/kol_submit_draft/1`) diuji hanya untuk memverifikasi keberadaan validasi kepemilikan — validasi berjalan sebelum penyimpanan.

**Keterbatasan:**
- Pengujian dilakukan terhadap data yang ada pada akun tersebut; skenario edge-case (campaign kosong, invoice kosong, KOL baru tanpa performa) tidak dicakup.
- Tombol aksi baris (mis. `Activate`, aksi status) berupa `javascript:void(0)` dan tidak diuji karena berpotensi mengubah data.
- Tidak ada pengujian beban/concurrency.
- Endpoint eksternal (Apify, KeyAPI, WhatsApp) tidak dipanggil untuk menghindari dampak pada produksi.
